# KEY — ресерч ЖК → лендинг: 3 промпта

Запускайте по порядку. Результат каждого этапа вставляйте во вход следующего.
Этапу 1 нужен доступ в интернет. Перед этапом 2 просмотрите Data Layer и поправьте вручную — это главная точка контроля.

**Что изменено относительно исходного промпта**
- Один проход на 15 частей → три этапа.
- Добавлено правило на случай, если источник не открылся.
- Тексты привязаны к статусам достоверности.
- Дубли (Паспорт, Part 1, Data Layer, Part 12) объединены в один Data Layer: значение + URL + статус + дата.
- Убран список из 10 «ролей».
- Добавлены лимиты на объём и проверка перед публикацией (реклама новостроек, ПД, права на изображения).
- Блок «когда будет шаблон» вынесен в этап 3Б.

## ЭТАП 1. Факты → Data Layer

```text
KEY — ЭТАП 1. ФАКТЫ → DATA LAYER

РОЛЬ И ЗАДАЧА
Ты — исследователь рынка новостроек.
Собери проверенную базу данных по жилому комплексу.
Не пиши рекламные тексты и не формулируй стратегию —
это следующие этапы.
Результат — Data Layer: таблицы фактов, где у каждого
значения есть источник, статус достоверности и дата проверки.

ИСХОДНЫЕ ДАННЫЕ
Основная ссылка: [ССЫЛКА НА ЖК]
Дополнительные ссылки: [ССЫЛКИ]
Файлы (если есть): презентации, PDF, планировки, прайс,
проектная декларация, материалы застройщика.

ДОСТУП К ИСТОЧНИКАМ
- Если источник не открылся (ошибка, сайт на JS, нужна
  авторизация) — напиши, какой именно, и не восполняй
  данные по памяти.
- Если у тебя нет доступа в интернет — остановись и скажи
  об этом до начала работы.
- Для каждого источника фиксируй дату, когда ты его смотрел.

ИСТОЧНИКИ (по приоритету)
1. Первичные: сайт ЖК и застройщика, проектная декларация,
   ЕИСЖС / наш.дом.рф, официальные PDF, презентации, новости.
2. Независимые: ЦИАН, Домклик, Яндекс Недвижимость, Авито,
   профильные СМИ, архитектурные издания, обзоры, интервью.
3. Инфраструктура: карты, транспортные сервисы, сайты школ,
   садов, клиник, ТЦ, парков и т.д.

СТАТУСЫ ДОСТОВЕРНОСТИ (обязательны для каждого факта)
VERIFIED — подтверждено первичным источником
CROSS-CHECKED — подтверждено несколькими независимыми
  источниками
DECLARED — заявлено застройщиком, независимого
  подтверждения нет
SECONDARY — найдено только во вторичном источнике
UNCONFIRMED — надёжно подтвердить не удалось
CONFLICTING — источники противоречат друг другу
DECLARED, UNCONFIRMED и CONFLICTING никогда не превращай
в установленный факт.

ЗАПРЕЩЕНО ПРИДУМЫВАТЬ
цены, сроки, площади, расстояния, время в пути, количество
квартир и корпусов, отделку, материалы, бренды, инфраструктуру,
виды, технологии, услуги, акции, ипотеку, доходность.
Нет данных → «Не найдено подтверждения в открытых источниках».
Данные расходятся → «Источники расходятся — требуется
ручная проверка».
Расстояния и время в пути указывай только если они взяты
из карт или сервиса — с названием сервиса и режимом
(пешком / авто / транспорт).

ЧТО СОБРАТЬ (блоки Data Layer)
1. basic — название, адрес, город, район, класс, статус,
   очереди, корпуса, этажность, количество квартир, сроки
2. developer — застройщик, девелопер, история, другие проекты
3. architecture — архитекторы, дизайнеры, фасады, материалы,
   окна, входные группы, лобби, лифты, высота потолков
4. landscaping — двор, озеленение, детские и спортивные зоны,
   террасы, безопасность, коммерция
5. apartments — форматы, площади, планировки, виды, террасы,
   балконы, особые форматы
6. finishing — варианты отделки (white box / чистовая /
   дизайнерская), материалы, бренды, сантехника, кухня,
   техника, кондиционирование, smart home
7. engineering — вентиляция, отопление, шумо- и теплоизоляция,
   доступ, видеонаблюдение, приложение, EV-зарядки
8. parking — парковка, условия
9. services — консьерж, охрана, клининг, доставка,
   управляющая компания
10. location — что рядом в 5 / 10 / 15 / 30 минут;
    отдельно пешком, авто, транспорт
11. infrastructure — рестораны, магазины, фитнес, школы, сады,
    медицина, парки, культура
12. pricing — цены, диапазоны, условия покупки, ипотека,
    рассрочка, акции
13. competitors — 3–5 сопоставимых проектов: локация, класс,
    диапазон цен (с датой), ключевые отличия.
    Без рейтингов и оценок.

ФОРМАТ ОТВЕТА
Для каждого блока — таблица:
Поле | Значение | Источник (URL) | Статус | Дата проверки
Если в блоке ничего не найдено — оставь блок с пометкой.

После таблиц:
A. CHANGE-SENSITIVE — поля, которые быстро устаревают (цены,
   наличие, акции, ипотека, рассрочка, сроки, остатки).
   Для каждого: DATE CHECK REQUIRED.
B. ПРОТИВОРЕЧИЯ — где источники расходятся и в чём.
C. ПРОБЕЛЫ — что не удалось найти.
D. ВОПРОСЫ КО МНЕ — не более 5, только те, без ответа на
   которые нельзя переходить к этапу 2.

ПРАВИЛА
- Только факты. Без оценок, эпитетов и рекламных формулировок.
- Фиксируй всё найденное, что относится к блокам. Что из
  этого показывать на лендинге — решим на этапе 2.
- Слоган или обещание застройщика — это DECLARED, не факт.

ПРОВЕРКА ПЕРЕД ОТВЕТОМ
[ ] у каждого поля есть источник и статус
[ ] нет выдуманных значений
[ ] противоречия вынесены в отдельный список
[ ] у change-sensitive данных есть дата
```

## ЭТАП 2. Стратегия

```text
KEY — ЭТАП 2. СТРАТЕГИЯ

РОЛЬ И ЗАДАЧА
Ты — стратег по недвижимости и контент-стратег KEY.
На входе — Data Layer из этапа 1.
Пойми проект и покупателя, найди реальные преимущества,
сформулируй позиционирование и стратегию лендинга.
Тексты и блюпринт — на следующем этапе.

ФИЛОСОФИЯ KEY
«KEY берёт сложность на себя, чтобы люди могли заниматься
главным.»
Покупателю нужно понять: что это за место → кому оно
подходит → почему может быть интересно → сколько это
стоит → что он получает → что делать дальше.
Без манипуляций, без ложного дефицита, без маркетинговых
обещаний, выданных за факты.

ВХОД
[ВСТАВЬТЕ DATA LAYER ИЗ ЭТАПА 1]
Цель страницы и аудитория, если уже известны: [...]

ПРАВИЛА
- Опирайся только на Data Layer. Не добавляй новых фактов
  (цен, сроков, характеристик, расстояний).
- Нужного факта нет → запиши в «Недостающие данные»,
  не додумывай.
- Основание для преимуществ — только VERIFIED и
  CROSS-CHECKED. DECLARED допустим с атрибуцией
  («по данным застройщика»).
- Всё про мотивы, страхи и поведение покупателя — гипотезы.
  Помечай «ГИПОТЕЗА» и отделяй от фактов.
- Каждый факт сопровождай ссылкой на поле Data Layer.
- Без рейтингов «лучший / худший».

ЧТО СДЕЛАТЬ
1. ДНК ПРОЕКТА (кратко, 7 ответов): Что это за проект?
   Для кого? Какую жизнь предлагает? Что человек получает
   кроме квадратных метров? Какое главное ощущение?
   Что делает проект узнаваемым? Какие характеристики
   реальные, а какие — только маркетинговые формулировки?

2. АУДИТОРИЯ: 2–3 сегмента. Для каждого:
   WHO / NEED / PAIN / FEAR / CRITERIA / OBJECTION /
   PROOF (какой факт снимает сомнение).
   Плюс: какую задачу решает покупка (JTBD).

3. КАРТА ЦЕННОСТИ (8–12 строк):
   Характеристика | Факт (поле Data Layer) | Польза |
   Эмоциональная ценность

4. ДИФФЕРЕНЦИАЦИЯ: сравни с конкурентами из Data Layer
   (локация, класс, цены, архитектура, благоустройство,
   квартиры, отделка, сервис). Найди реальные точки
   отличия. Раздели STANDARD и DIFFERENTIATOR.

5. ПРЕИМУЩЕСТВА: TOP 10 → TOP 5 → TOP 3 → ONE CORE IDEA.
   Если честно свести к одной идее нельзя — объясни почему.

6. ПОЗИЦИОНИРОВАНИЕ:
   CATEGORY / AUDIENCE / NEED / DIFFERENTIATOR /
   REASON TO BELIEVE

7. КАРТА АРГУМЕНТОВ (5–8 возражений):
   Возражение | Факт | Аргумент | Доказательство
   Без давления.

8. АРХИТЕКТУРА ДОВЕРИЯ: что создаёт доверие (документы,
   застройщик, реальные фото, ход строительства, прозрачные
   цены, условия покупки, FAQ), что уже есть, чего не хватает.
   Последовательность: интерес → понимание → доказательство →
   доверие → действие.

9. ПРИОРИТЕТЫ ИНФОРМАЦИИ:
   P0 — без этого лендинг теряет смысл
   P1 — влияет на решение
   P2 — для глубокого изучения (раскрывающиеся блоки)
   P3 — только в базе, не на лендинге

10. СТРАТЕГИЯ ЛЕНДИНГА: главная задача страницы; главный
    и вторичный CTA; главный сценарий пользователя;
    роль KEY. Баланс: PROJECT FIRST → KEY AS GUIDE
    («KEY помогает разобраться в проекте и подобрать решение
    под задачу клиента»). Не превращай лендинг в рекламу
    агентства.

ФОРМАТ
Нумерованные разделы 1–10, таблицы там, где указано,
в остальном короткие абзацы или списки. Без воды.
Объём — не больше 4 страниц.
В конце: «НЕДОСТАЮЩИЕ ДАННЫЕ» и «ВОПРОСЫ КО МНЕ» (до 5).

ПРОВЕРКА ПЕРЕД ОТВЕТОМ
[ ] нет фактов, которых нет в Data Layer
[ ] гипотезы помечены
[ ] главное отличие подтверждено фактами
[ ] нет пустых эпитетов
[ ] KEY представлен как помощник, а не как реклама
```

## ЭТАП 3. Лендинг: блюпринт и контент

```text
KEY — ЭТАП 3. ЛЕНДИНГ: БЛЮПРИНТ И КОНТЕНТ

РОЛЬ И ЗАДАЧА
Ты — UX-стратег и редактор коммерческих текстов KEY.
На входе — Data Layer (этап 1) и стратегия (этап 2).
Спроектируй структуру лендинга именно для этого ЖК
и напиши тексты. Не копируй стандартную структуру
автоматически.

ВХОД
[DATA LAYER]
[СТРАТЕГИЯ]
[ОГРАНИЧЕНИЯ / ШАБЛОН, если есть]

ПРАВИЛА
- Цифры, названия и характеристики — только из Data Layer.
  В блюпринте указывай поле-источник.
- В тексты — только VERIFIED и CROSS-CHECKED. DECLARED —
  с атрибуцией («по данным застройщика»).
  UNCONFIRMED и CONFLICTING не использовать.
- Цены, сроки, акции, ипотека, рассрочка — помечай
  DATE CHECK REQUIRED и дату актуальности.
- Не показывай всё, что найдено. На лендинг — то, что нужно
  покупателю, чтобы понять проект, доверять ему и сделать
  следующий шаг.

СТИЛЬ KEY
Уверенно, спокойно, точно, по-человечески, интеллектуально.
Без крикливых продаж, канцелярита и рекламной воды.
Принцип: «Сначала пойми, потом продавай».
Конкретика → факт → польза → смысл.
Не использовать: пустые эпитеты, клише, «уникальный»,
«лучший», «эксклюзивный», «не имеет аналогов» (без
доказательства), искусственный дефицит, давление.
Пример тона. Не так: «Успейте купить уникальную квартиру
мечты!» А так: «Здесь важна не площадь сама по себе,
а то, как устроена жизнь внутри неё» — но только если это
опирается на реальные характеристики проекта.

ЧТО СДЕЛАТЬ
1. ПЕРВЫЙ ЭКРАН — 2–3 варианта. За несколько секунд он
   отвечает: что это, где, почему обратить внимание,
   для кого, что делать дальше. Не перегружать.

2. БЛЮПРИНТ — таблица:
   № | Блок | Задача | Главный смысл | Контент (поля
   Data Layer) | Визуал | CTA | Приоритет (P0–P3)
   Это инструкция для дизайнера и разработчика.

3. ТЕКСТЫ ПО БЛОКАМ — для каждого блока: заголовок,
   подзаголовок, текст, почему блок стоит именно здесь.

4. UX-СЦЕНАРИЙ: увидел → заинтересовался → понял концепцию →
   увидел преимущества → проверил локацию → посмотрел
   квартиры → получил ответы → увидел доказательства → CTA.

5. ПЛАНИРОВКИ (если есть): 3–5 «наиболее показательных»
   (не «лучших»): площадь, комнаты, особенности, кому
   подходит, какие зоны подсветить.

6. ФИЛЬТРЫ / КАЛЬКУЛЯТОР — только те, что реально нужны
   пользователю.

7. FAQ — 10–15 вопросов:
   Вопрос | Короткий ответ | Источник (поле Data Layer) |
   Важность
   Приоритет — вопросам, которые мешают оставить заявку.

8. CTA — под этап решения: подобрать квартиру, получить
   актуальные варианты, узнать стоимость, посмотреть
   планировки, получить презентацию, записаться на просмотр,
   поговорить с брокером KEY. Не только «Оставить заявку».

9. ФОРМА — минимум полей:
   Поле | Зачем нужно | Кто использует | Можно ли убрать
   Отдельно: согласие на обработку персональных данных.

10. АНТИ-ПАТТЕРНЫ — какие блоки перегрузят страницу, какие
    факты не нужны, какие тексты слишком рекламные, какие
    визуалы дублируют друг друга, что убрать в раскрывающиеся
    элементы, где пользователь может потеряться.

11. CONTENT INVENTORY — что нужно подготовить: фото, видео,
    3D, планировки, карты, инфографика. Для каждого: что
    именно и есть ли право использовать (материалы
    застройщика).

12. ПРОВЕРКА ПЕРЕД ПУБЛИКАЦИЕЙ:
    - все change-sensitive данные сверены, стоит дата
    - «от X ₽»: понятно, на какие квартиры и условия это
      относится
    - ипотека и рассрочка: условия указаны полностью
      и актуальны
    - соответствие требованиям к рекламе новостроек
      (38-ФЗ «О рекламе», 214-ФЗ), обязательные сведения
      о застройщике и проектной декларации — уточнить
      у юриста
    - форма: согласие на обработку ПД (152-ФЗ)
    - права на фото и рендеры застройщика
    - нет неподтверждённых утверждений и обещаний
      доходности

ПРОВЕРКА ПЕРЕД ОТВЕТОМ
[ ] понятен первый экран
[ ] CTA соответствуют этапу решения
[ ] нет информационной перегрузки
[ ] каждая цифра есть в Data Layer
[ ] страница отвечает на 5 вопросов покупателя: Что это?
    Почему мне может подойти? Что именно я получаю?
    Почему я могу этому доверять? Что мне сделать дальше?
```

## ЭТАП 3Б. Сборка лендинга по шаблону

Используйте, когда есть шаблон (HTML / React / Figma).

```text
KEY — ЭТАП 3Б. СБОРКА ЛЕНДИНГА ПО ШАБЛОНУ

Вход: шаблон, Data Layer, стратегия, блюпринт и тексты
из этапа 3.
Запрос: «Создай лендинг этого ЖК».

ПОРЯДОК РАБОТЫ
1. Изучи шаблон: блоки, дизайн-систему, ограничения.
2. Сопоставь блоки шаблона с блюпринтом: какие подходят,
   какие изменить, каких не хватает.
3. Сохрани визуальную систему шаблона, если я не просил
   иначе.
4. Используй только данные из Data Layer со статусами
   VERIFIED / CROSS-CHECKED (DECLARED — с атрибуцией).
   Ничего не выдумывай.
5. Не оставляй lorem ipsum и заглушки там, где в Data Layer
   есть данные. Где данных нет — оставь явную пометку
   [НЕТ ДАННЫХ], не заполняй догадками.
6. Адаптируй тексты под конкретный ЖК, перенеси ключевую
   идею и позиционирование.
7. Не перегружай страницу: P2 — в раскрывающиеся элементы,
   P3 — не показывать.
8. Проверь мобильную версию, логику CTA и форму.
9. Перед выдачей проведи QA: сверь каждую цифру и факт
   с Data Layer, проверь change-sensitive данные и чек-лист
   публикации (этап 3, раздел 12).
10. В конце дай список: что взято из шаблона без изменений,
    что изменено, что добавлено, что осталось без данных.

ПРИНЦИП
Не «заполнить шаблон информацией о ЖК», а превратить
готовую дизайн-систему в убедительную страницу конкретного
жилого комплекса.
```
