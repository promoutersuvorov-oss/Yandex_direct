# Mapping паспорта ЖК → runtime-конфигурация KLanding

Версия: 1.0.0  
Статус: спецификация сопоставления. Это не означает, что автоматический конвертер уже реализован.

## 1. Разделение слоёв

| Слой | Назначение | Текущий формат |
|---|---|---|
| Паспорт | Факты, источники, статусы, актуальность, пробелы | `PROJECT_PASSPORT_SCHEMA.json` |
| Профиль проекта | Название, адрес, характеристики, маркетинговые тексты, SEO, контакты | `project-config.<slug>.js` → `window.KEY_PROJECT_PROFILE` |
| Контент | Массивы изображений, карточек, POI, квиз и модальные тексты | `content-config.<slug>.js` → `window.KEY_PROJECT_CONTENT` |
| Интеграции | Webhook, аналитика, CRM и ссылки документов | Только согласованная конфигурация; не переносить автоматически из K15 |
| Манифест модулей | Включение и порядок секций | Использовать только если это поддерживает текущий runtime |

## 2. Рекомендуемое сопоставление

| Поле паспорта | Возможный профиль runtime | Примечание |
|---|---|---|
| `project.name.value` | `project.name` | Только после проверки статуса |
| `project.city.value` | `project.city` | Не подставлять гипотезу как факт |
| `project.address.value` | `project.address` | Проверить официальный источник |
| `project.officialSite.value` | SEO/canonical | Не конструировать URL |
| `positioning.valueProposition.value` | `marketing.heroSubtitle` | Редакторская адаптация не должна менять смысл |
| `positioning.advantages[]` и claims | Тексты выбранных секций | Сохранять claim IDs в QA-реестре |
| `media[]` | Пути ассетов в profile/content | Проверить принадлежность ЖК, права и существование файла |
| `location.*` | `project.mapLat/mapLon/mapCity2gis` | Только проверенные координаты |
| `location.points` | `PLACES`, `MAP_FEATURED` | Только если структура совпадает с контрактом renderer |
| `apartments.*` | `project.facts.*` | Только поля, реально поддерживаемые движком |
| `media[type=plan]` | Планировочный renderer | Не направлять интерьерные рендеры в слот плана |
| `commercial.*` | `vars`/marketing | Нужны дата проверки и срок актуальности |
| `conversion.*` | CTA/form config | Endpoint и согласия должны быть реальными |
| `modules[]` | Манифест секций | Если манифеста нет, порядок может быть зашит в HTML |

## 3. Правила преобразования
1. Не публиковать поле со статусом `missing`, `conflict`, `hypothesis` или `needs_update` как подтверждённый факт.
2. Не терять источник: хранить source IDs и claim IDs в паспорте/QA-артефакте, даже если они не отображаются пользователю.
3. Пустой массив означает отсутствие подтверждённого контента, а не разрешение использовать данные другого ЖК.
4. Не использовать интерьерный рендер как план квартиры.
5. Для цен, акций, ипотечных условий и наличия квартир фиксировать дату проверки.
6. Перед созданием профиля проверять фактические типы, обязательные поля и поведение пустых значений в движке.
7. Поля без runtime-аналога помечать как неподдерживаемые; не отбрасывать их молча.
8. Не копировать K15-координаты, контакты, privacy URL, endpoint, счётчики, документы или локальные имена медиа.
9. Демонстрационные значения не должны попадать в production.

## 4. Проверки перед использованием
- Сверить паспорт со схемой JSON Schema.
- Проверить mapping каждого выбранного модуля.
- Убедиться, что все пути медиа существуют.
- Найти старое название, адрес, город, застройщика и имена изображений.
- Проверить поведение пустых значений.
- Не объявлять автоматическую генерацию конфигурации готовой, пока преобразователь не реализован и не протестирован.

## 5. Ограничение
Это документированный контракт для согласования двух моделей данных. Автоматический паспорт → runtime-конвертер не реализован этим документом; совместимость необходимо проверять по фактическому коду.


## Актуальная схема KLanding

Текущая схема в `schemas/project-passport.schema.json` отличается от старой схемы Agency. При проектировании адаптера учитывать фактические поля текущей версии:

| Текущий паспорт | Назначение |
|---|---|
| `project` | Идентичность ЖК и базовая локация |
| `facts[]` | Атомарные утверждения и их доказательная база |
| `advantages[]` | Преимущества, которые должны ссылаться на факты |
| `infrastructure[]` | Объекты окружения и локальные hooks |
| `offers[]` | Сценарии CTA / предложения |
| `assets` | Изображения, видео, планы, документы, карты |
| `contentStrategy` | Core idea, CTA, приоритет аудитории, решения по модулям и визуальное направление |
| `verification` | Проверки, конфликты и пробелы |
| `commercial` | Внутренние настройки KEY; не публиковать и не отдавать клиентскому JS |

Не переносить legacy schema и legacy generator из Agency. До написания конвертера проверить текущий HTML/runtime и зафиксировать точное соответствие типов и полей. Схема паспорта не должна автоматически считаться схемой runtime-конфигурации.
