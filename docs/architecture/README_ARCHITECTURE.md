# KEY Landing Generator — этап 04: Data Model

Этот пакет фиксирует следующий слой архитектуры после аудита K15 и библиотеки модулей.

## Файлы
- `project-passport.schema.json` — JSON Schema паспорта ЖК.
- `project-passport.example.json` — безопасный пустой пример паспорта, без выдуманных фактов об объекте.
- `PROMPT_1_5_PROJECT_PASSPORT.md` — промпт агента для сбора и проверки данных.
- `DATA_MODEL_SPEC.md` — правила модели и взаимодействия с конфигурациями.

## Главный принцип
Факт, маркетинговая интерпретация и коммерческая настройка KEY — три разных сущности. Данные нельзя публиковать только потому, что они присутствуют в JSON: они должны иметь допустимый статус и источник.

## Статусы фактов
`verified`, `provisional`, `hypothesis`, `missing`, `conflicting`, `expired`.

## Важное ограничение
Это следующий проектный артефакт, а не утверждение, что текущие `project-config.k15.js` и `content-config.k15.js` уже проверены на совместимость. Сверку нужно выполнить на реальных файлах; после неё следует зафиксировать адаптер/миграцию, а не ломать работающий эталон.
