## 4. Почему production-прогон остановлен

### Данные и стратегия

В исходном паспорте:
- нет активных операционных офферов;
- нет актуальной матрицы доступных квартир и подтверждённых планировок;
- нет одобренных изображений с подтверждёнными правами;
- нет утверждённого квиза подбора;
- есть неразрешённые конфликты по строительному статусу/срокам и явный флаг ручной проверки.

Отдельный Positioning Gate review для КД «905» имеет статус `blocked`: сегмент, потребность, ценовой диапазон, канал трафика и конвертер остаются гипотезами или требуют подтверждения. В частности, нет первичной матрицы лотов, валидации аудитории через CRM/интервью, проверки спроса/аукциона и операционно утверждённого оффера KEY.

### Runtime и интеграция

Canonical CLI принимает отдельные входы:
1. Project Passport;
2. Marketing Copy;
3. LANDING BRIEF;
4. Public Integration Config.

Knowledge и Landing Inputs создаются автоматически из паспорта — отдельная ручная перекладка этих внутренних моделей не нужна.

Но Marketing Copy должен быть утверждён человеком и связан с конкретными fact IDs; production требует approved LANDING BRIEF с пройденным Positioning Gate и проверенную интеграцию лидов/согласий. Эти входы нельзя автоматически помечать approved. Сейчас у КД «905» нет оснований обходить эти контрольные точки.

## 7. Решение

**Не строить ещё один слой архитектуры только ради автоматизации.** Следующий полезный инженерный шаг — убрать подтверждённую ручную перекладку Marketing Copy / Brief, но только после фиксации реального формата входных материалов и сохранения раздельных статусов `draft` / `approved`.

Для КД «905» production-сборку пока не запускать: сначала закрыть P0-данные и операционный оффер. До этого допустимы только внутренние review-превью с явной маркировкой, что они не предназначены для публикации.
